## 什么让任务持续有价值
在已批准范围内，新失败样例、用户时间点反馈、已确认素材缺口或依赖版本变化产生下一任务。主代理每日依据证据补充小队列，不靠Plan自由发明产品方向。单个任务完成即结束，后续任务必须有新的输入/假设/验收；池空休息。到期扩大范围或继续下一周期需要新的决定。

不因时间到点、token有余或想增加测试数量而生成重复任务。待试听作品不妨碍独立工程问题修复，但不能被当成用户已同意的音乐基准。

## 边际价值停止规则
- 连续3个已完成、可比实验没有解决失败案例或产生有用证据，暂停该假设并说明原因；用户没听不计失败。
- 未试听候选积压达到2组则暂停继续生成音乐，转做已批准的独立技术任务；平局/都不要记录原因，不扩张为整个方向永久无价值。
- 达到预先声明的技术目标且无新反例就结束该任务；不反复看留出集调参。数据不足时交付基线与未决点，不宣称准确率达到未经定义的门槛。
- 超时即隔离（参照上次 1200s/exit143 事故），unknown 不换 ID 重提、不无限重试；
- 每家族每周期在池任务数设硬上限，池空即停；总并行独立包任务 ≤2。

## Holdout / 黄金夹具
- 冻结已有文件哈希作为保护基准，在隔离目录重渲染；已知信号/人工标注样本用于正确性。v2尚待听感反馈，只能作数据保护案例，不能作审美真值。现有6新＋46工具测试是事实基线，不是优化目标。
- 内容身份按源录音/内容家族拆分开发集、校准集和留出集；同句变体不能跨集合泄漏。人工标签区分同内容、不同内容和不确定；没有标签时不假造ground truth。
- 盲审记录长期保留，禁止任何伪造人工 Keep。

## 反指标游戏
- 续期排序只看音乐价值与主代理减负；明确禁止按测试数、轨数、token 数优化或考核；
- 验收一律行为级：保护轨 hash、SHA 溯源、可回退、实际听感。

## 前7天建议顺序（依赖顺序，不保证每天完成一项）
先补运行闸门：队列、并发占位、验收积压和过期恢复做离线验收，再启用试运行。

1. **可复现基准**：已知信号＋本地用途已核验录音的最小索引、保护快照、按源分组的评测清单；记录已有失败，不增加整库爬取。
2. **真实修订验收**：用正式翻采工程的隔离副本验证“换回答句但鼓/Bass/外部区间不动”，扩大恢复/取消的真实反例；缺身份标注就明确待确认。
3. **一个音乐假设**：用户确认素材/目标后，比较两种切法或鼓感；或者有标签时做同内容识别实验。最后提供最多2个音量匹配候选供试听。

Live是重要缺口，但环境未恢复不能把反复UI重试当夜班工作。完整自动身份识别、新素材源和其他未选功能不因出现在本表就获得实施授权。
