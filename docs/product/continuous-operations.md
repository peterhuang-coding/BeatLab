# BeatLab Coding Plan 持续运行协议（提案，未激活）

状态：**提案，尚未激活**。本次完成方案与任务池，原每日22点调度保持。拟议试运行7天，时区Asia/Shanghai：执行机会22:00 / 00:00 / 02:00，Codex集中复审09:00。用户可选定任务池的一个范围，范围内小任务由主代理持续拆解，不需要每个技术改动都重新问。

可选方式：现有每日一次成本低，但反馈慢；推荐多时点唤醒当前聊天、Plan执行、主代理验收；另建常驻服务维护成本更高，当前不做。原生心跳仍需主代理调度，没有独立于主额度的无限执行能力。

## 1. 定时器与并发

- 首选：更新现有beatlab心跳为22/00/02/09四个时点，按本地时段选择执行或集中复审，共享一个队列和锁，保持当前聊天。09点只复审和安排下一轮，不启动耗时新任务。每轮都有轻量状态/边界检查，不能等到早上才发现旧请求被重复提交。
- 备选（仅限现机制无法单定时器多点唤醒、且证明确有必要）：三个独立唤醒共享同一队列与同一把锁，抢不到锁立即退出，不得重复执行。
- 每波最多2个独立任务包；同账号跨任务并发上限2，重叠文件串行采用。**缺口**：当前claude_plan.py只有单任务暂存与幂等，没有持久自动任务队列或账号共享并发闸门。启用试运行前先验共享占位机制，不能靠多开心跳绕并发限制。
- 禁止补跑爆发：错过的唤醒不追跑、不批量补偿；每次唤醒只做一轮巡检。

## 2. 身份、暂存与冻结

- 逻辑任务ID保持稳定；每次尝试关联候选入口、尝试序号、base SHA、输入哈希和授权范围。不能因换base/模型/目录重置旧请求账本。提交前持久化记录和占位，未知结果不重复派发。
- approved范围内、依赖已验收、验收标准完整的任务才进入ready；worker交付后进入awaiting_review。必要字段包括允许文件、最小可外发材料、精确验收命令、时间/数据预算、停止条件和父任务。只外发公开/合成/脱敏材料，真实录音在本地处理。
- stale输入先停采用并比较差异；unknown先检查原状态/日志/进程/稳定产物，不改ID重发。进程结束、产物稳定且独立验收通过时，可恢复草稿，但保留原unknown记录；不得把超时写成worker完整成功。
- 建议每包20分钟上限、每次唤醒最多45分钟，只派一波2包；截止前不足完整预算就不启动。额度/冷却可等则等待；使用当前已验证且匹配的套餐入口，不启用额外付费。每候选常规一次、质量修正最多一次，旧任务更紧限次优先。
- 用户最新质量偏好：在已授权套餐中优先使用已验证、适合任务的最高能力模型，并显式请求该入口支持的最高思考档；Seed Evolving按最新task-tiering使用原生high。派发前核对实际thinking/effort参数，入口不支持则先补齐核验，不只在提示词写“高思考”，也不为省下游token降档。不把high或Auto当全模型效果排名。文件读写/测试限于交接白名单预授权；不扩大整机权限。新偏好适用于下一尚未提交任务，本轮已结束的两个文档包不重发、不追认已使用显式high。

## 3. 评审背压、过期与恢复

- 未审包与在途包的预留数量合计最多4个；派前原子占位，满额后只收齐/复审。两组音乐候选未试听时暂停音乐生成，不阻塞已批准的独立工程工作。
- 技术任务状态：proposed → ready → running → awaiting_review → accepted / needs_revision / rejected；另有blocked/unknown/paused。accepted只代表技术验收；音乐的用户Keep单独保存，不能混为一类。
- 7天是试运行授权窗口，不是用户试听的最后期限；不因7天未听自动拒绝或删除作品。启用时保存明确start/deadline、原automation全部字段与恢复标志；每次派发先检查deadline。到期停止新派发，收齐/保留在途任务，再用原生automation_update恢复原名称、prompt、时间、ACTIVE、target并逐项读回；离线错过到期，只能在恢复后的首次唤醒处理，不能承诺离线准点恢复。
- 队列不以“有commit”当有价值。连续3轮已完成实验无有效增量则停止该假设，记录具体问题；技术目标达到即结束任务。没有新输入和问题时安静休息。

## 4. 交接契约与每日产出

- handoff-result.json沿现有入口契约：status仅completed/blocked，summary、changed_files、tests（真实命令/退出码）、blockers、memory_delta、next_steps。外层runner result与任务账本另记unknown，不能往固定schema虚构状态。
- 主代理每日09:00独立看diff、重跑相关验收、检查输入/旧作品保护；改音频就验证真实渲染，改播放就验证真实HTTP/浏览器，改工程就区分文件检查与Live实测。冻结的留出集与反例独立保存，不能让同一worker改评价标准给自己放行。
- 验收通过后由主代理顺序采用到执行分支，必要集成验证后普通commit/push并核对远端SHA，回填Notion与Hub。CC不直接写原项目、不自行push/main合并。技术改动的这一流程在用户批准范围内执行；不需要把每个commit都留给用户审批。
- 每天只交一份简报：解决的具体问题、真实证据与提交、未解决项、最多2个值得听的候选、需要用户决定的一点。没有变化不发空日报。仅完成/重要失败/需操作时通知；用户在方便时试听，不要求09点在线。
- 不承诺无限额度或主代理额度耗尽后的独立调度。已启动子进程只在自身期限内运行；进度提前落盘，冷却/登录/主入口恢复后按原账本检查，不补跑错过的时点。
