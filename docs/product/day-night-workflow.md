## 白天的最小操作

1. 看上一轮交付卡里的结论、试听/结果链接和待你决定的问题。
2. 选择一个任务，把状态从「待定方向」改成「今晚执行」。如有取舍，在「你的决定」里写清；只改为「今晚执行」表示接受该卡现有范围与验收标准。
3. 可在当前 Codex 任务直接说「今晚执行 R01，先面向我自己的创作」。代理须把这条决定回填对应卡片和主线。
4. 技术验证完成后状态为「待你验收」；你确认方向或实际听过后，才记为「已完成」。

R01–R06 的批准只覆盖调研及其卡片里的验证范围。研究报告提出的新功能、付费方案或上架计划，仍要形成下一张可选择的任务卡。

## 夜班如何恢复

调度使用当前 Codex 任务的 heartbeat，每天北京时间 22:00 发起一轮。运行依赖这台 Mac 的本地 Codex 环境和 2TB 硬盘可用。自动化已创建并核验配置，尚无首轮定时执行证据。

每轮先读项目 AGENTS、执行主线、最近两份轮次摘要、git status；再读取 Notion 卡片的最新状态、范围和「你的决定」。

- 先恢复仍在「执行中」且与主线对应的唯一任务；「暂停」或用户取消立即停止。
- 没有正在执行的任务时，从「今晚执行」选一项。多选时先按用户明确顺序；没有顺序则按优先级、编号选择一项，其余保留排队。
- 将任务编号、Notion URL、用户决定、范围、验收和起始 commit 写入主线，状态改为「执行中」，才开始工作。
- 若 Notion 无法读取且本轮没有可核验的明确用户选择，不把 Git 中的待办/建议或旧快照当作新决定。
- 对话与 Notion 相互冲突、或范围/依赖不足以执行时，记录一个具体待决策项并停止受影响工作。

## 执行与交付

研究使用当时可验证的官方资料/论文/仓库或实际可访问的产品流程，区分事实、推断、建议；音乐创作保留原句、solo、成品和对应版本，不代替用户填听感。

代码工作先检查远端与本地分支，用隔离工作区保留当前可用音乐；仅在卡片范围内修改并运行适当验证。main 3d333fe 与采样分支尚未整合，E01–E03 应对准实际包含问题的版本，不能在错误分支宣称修好。

每轮完成后：

1. 保存报告/配方/最小改动及实际验证结果，更新 .claude/autopilot/rounds/ 摘要和主线；复盘写入本项目 Hub。
2. 检查暂存文件，commit 并普通 push 至当前执行分支；带上相应计划和进度，不 force push、不擅自合入 main。已完成 push 后把最终 commit 链接回填 Notion，避免把本地提交当远端成功。
3. 更新 Notion 卡的结果链接、验证结论与「待你验收」状态。没有产物或验证失败就据实记录，不标已完成。
4. 遇到需要新方向、连续三次相同失败无进展或环境阻塞时，保存恢复点和具体问题；不原样无限重试。

仅在完成、实质进展、失败或需要用户行动时通知；没有选定任务或状态没有可行动变化时保持安静。文档和 Notion 使用同一任务编号。Notion 是白天的决策入口，主线记录已确认执行快照；研究正文和实现以 Git 为准。

## 内容边界

素材/作品/模型/数据库留在 2TB，Git 与 Notion 保存文档、配方、来源说明和可审阅链接。保留已认可作品，测试使用隔离目录。不因批准调研而购买订阅、发消息给他人、公布新歌或接受平台协议。
