# BeatLab 采样制作手册

## 已确认的创作方向

用户认可 Windowlight 的和声与律动，要求加入人声和复杂变化；随后明确希望从一段已有音乐里取句，通过变调、前后切、重复和重排形成新主题。Dust Letters 的乐句翻采得到“很好很好”的反馈。原版、翻采版和反馈应绑定各自音频哈希，不能把上一版好评当成下一版验收。

复杂度优先来自同一主题的变化：前半句重复，后半句回答；保留能记住的动机，再改变句尾、音区、节奏或演奏顺序。新增人声、鼓花和音色需要有具体音乐作用。MIDI 与鼓垫是继续创作的工具。

## 一次翻采的最小流程

1. **选句。** 先找有辨识度的人声、和弦演奏、弦乐回应或旋律尾音。保留足够的前后语境；单个音色与完整乐句分开标记。源作品链接、原始文件、时间范围和许可依据随素材保存。
2. **找到主题。** 先试一段 2–4 小节的主题，验证采样本身是否值得重复。当前 Dust Letters 是明确人工选择的配方；自动目录轮换不等于自动挑出了好音乐。
3. **切片并变换。** 保存每一块的源起止、目标长度、半音变化、倒放状态和 MIDI note。短淡入淡出防止切点爆音；独立时间伸缩与变调让目标节奏可控。不要按目标 BPM 反推源乐句小节数。
4. **重新演奏。** 先建立一个反复出现的主句，再用截短重复、换序、句尾倒放、升/降八度做应答或过门。连续多小节都碎切会失去主题，要通过实际试听决定密度。
5. **编配。** 鼓和 Bass 跟随采样的重音与和声；低音保持明确音区。不同完整音乐层叠加前先听 solo，避免把采样里已有的伴奏与新增声部挤在一起。
6. **比较与反馈。** 固定输出原片段→采样 solo→成品。反馈分清“素材没感觉”“切法不对”“鼓/混音不对”，并注明时间点。响度比较说明实际采用 RMS 还是 LUFS，不用峰值和测试数量替代听感。
7. **交付。** 保留音频、MIDI、切片映射和来源。成品音频工程与可编辑采样器分别说明；XML 或文件引用验证不能替代 Live 实际发声、保存和回渲染。

## 老歌素材路线

当前已接入 Citizen DJ 的 National Jukebox Blues / Jazz 公开目录，适合探索早期演唱、钢琴、管乐与合奏的乐句。官方提供可下载的片段及合集 Rights & access 说明；入库状态以具体页面为依据。它提供的是早期录音，不能因为“年代久”就承诺等同 60–70 年代 Soul 的质感。[Blues 合集](https://citizen-dj.labs.loc.gov/loc-jukebox-blues/use/)、[Jazz 合集](https://citizen-dj.labs.loc.gov/loc-jukebox-jazz/use/)。

下一批创作选材优先考虑：一句有情绪的人声及尾音、短小的钢琴/吉他和弦连接、弦乐或管乐的回答句。60–70 年代 Soul/Gospel、老电影配乐和其它年代录音作为待探索方向；需要更贴合这些目录时，再接入提供完整录音与清样流程的来源，例如 [Tracklib Songs](https://www.tracklib.com/)。尚未开通该来源或购买素材。

## 已验证的工程方法

- 抓取先发现公开目录，再限量下载；从不同作品轮换取材。页面结构或许可文字改变时停止该批发现并保留错误。
- 文件按内容哈希去重；同一音频出现在不同合集也只入库一次。下载缓存校验 SHA，失败不产生完整文件。保留官方目录快照、媒体链接和获取时间。
- 两种偏移都保存：页面显示的秒级起始标签、官方 remix 参数里的毫秒偏移。两者可能不同，尚未与原始整曲逐采样点核对。
- 网络失败必须进入统计和非零退出码；不能只打印错误、总结果却显示成功。主 CLI 的参数必须实际传到下载执行层。

证据与适用边界：[翻采交付计划](superpowers/plans/2026-09-13-phrase-sample-flip.md)、[老歌入库计划](superpowers/plans/2026-09-13-old-record-crate.md)、`tests/test_sample_flip.py`、`tests/test_citizen_dj.py`。上述方法有一次明确音乐基准和真实入库验证；自动音乐偏好学习、持续挑出好乐句和全自动发布仍待实现。
