## 2. MVP 的范围与取舍

| 路线 | 得到什么 | 取舍 |
|---|---|---|
| 先做好创作闭环，再接单一来源和单一店铺（推荐） | 先证明用户会保留、会继续制作，再验证售卖 | 商业接入晚于第一轮听感验证 |
| 先做在线收藏与 DJ 歌单 | 更早得到参考音乐管理能力 | 生成质量和反馈仍未验收 |
| 同时铺开模型、双机和多平台发布 | 功能覆盖广 | 出错原因与音乐改进难以分开判断 |

**M1：可用创作 MVP。** 输入 5 个真实、完整且使用许可明确的音频样本，挑出主乐句，产出最多 3 个 60–90 秒草稿；用户能听原片段/分层/成品，给出原因，得到一个实际改变的新版本；保留后能打开真实 Ableton 音频工程继续制作。

**M2：完整目标的第一轮试运行。** 在 M1 基础上接一个经过验证的网络素材来源，按偏好自动发现、下载、入库与去重；把用户保留的 beat 扩展成完整编排，生成商品草稿包，并在一个平台完成 1–3 首受监督上架试验。记录上架结果、试听和用户使用/订单结果。M1 完成不等于 M2 或整个项目完成。

MVP 默认一种主风格：留白较多的采样型 hip-hop / soul。R&B 作为对照方向。先不同时优化大量曲风；该默认来自当前项目方向，仍由用户实际选择校准。

本版后置：全网自动下载、批量无人值守上架、双机调度、个性化大模型训练、复杂推荐系统、自动修改 DJ 私有数据库、完整 Drum Rack/MIDI 音色还原。DJ 第一版只交付固定路径音频与 M3U8；实际软件导入在设备/软件确认后验收。

### 阶段 1：先修音乐的节拍、音区和层次

**修改：** `pipeline/moments.py`、`recipes.py`、`compose.py`、`render.py`、`score.py`、`report.py`；若现有函数不能承载全局分析，新增 `pipeline/analyze.py` 作为单一音频分析入口。

**验收文件：** 新增 `tests/test_musical_alignment.py`、`tests/test_arrangement_constraints.py`。

- [ ] 保存 source BPM、beat/downbeat 时间列表、调性、置信度与分析版本；切片从源拍网格换算到目标拍网格，原始弱起/空白不能当第一下拍。
- [ ] 调名区分音级和八度；Bass 先映射到明确的低音音区（初始 MIDI 28–47），低置信度时允许关闭 Bass 或人工指定，不使用最强旋律音高直接当 Bass。
- [ ] 首个稀疏配方固定一个主乐句、默认零个额外旋律素材、一套鼓和可选 Bass；配方、文件来源与实际渲染层一致。
- [ ] 原曲已经带鼓/Bass 时，先分别试听原曲层和新增层，选择拆轨、关闭新增层或明确保留；不把所有层默认相叠。
- [ ] Review 同时展示原片段、处理片段、成品和各层 solo；显示实际来源区间与变速，不用分析分数描述“好听程度”。
- [ ] 使用同素材/同 BPM/同鼓与 Bass/同 seed 的基线和“仅去掉辅助旋律层”版本做第一组音量匹配 A/B。用户“嘈杂”的原话只关联真实试听对象，不自动映射成 no_space、降噪或差评。
- [ ] 已试听旧曲若原始音源仍缺失，改用完整基准样本做新实验并明确标注；不能称精确重做了旧曲。

**数值用例：** 120 BPM 的 8 小节为 16 秒；变到 92 BPM 后仍为 8 小节，时长约 20.869565 秒。带一秒前置空白的样本，首拍应跟随标注而非 0 秒。一个字段写对但实际音频仍漂移，不算通过。

**模型策略：** 先以现有 DSP 和人工校准的拍网格作为对照，评估 Beat This! 在 5 个基准样本上的拍点/下拍、运行时间和内存。明显改善后才设为默认；结构模型和 RoFormer 在发现对应错误时再比较。基准、代码/权重许可和本机运行证据必须一起记录。依据上一轮 [模型调研](/Volumes/SanDisk2TB/claude-pm-hub/projects/beatlab/audio-model-research-2026-09-12.md)，不声称模型已安装或有统一最优。

**通过条件：** 已知节拍用例正确、Bass 音区受控、必要层无缺失；用户能听见并选择层数不同的版本。第一轮即使用户仍不喜欢，也要定位具体因素再迭代，不把文件生成成功当作阶段音乐验收。

- [ ] 用户在 Live 实际做一次静音/片段移动并保存；手动记录“已打开并继续制作”，不能用 Export 点击次数推断真实使用。

**M1 通过条件（建议实验门槛）：** 连续 5 轮真实素材完整评审，每轮最多 3 候选；至少 2 轮有用户愿意保留的候选，其中至少 1 首在 Live 打开并继续编辑。三次反馈实验均产生预期参数和音频变化，至少一次新版被用户选中。所有技术用例通过。数量是本项目试验门槛，不是已达到成绩或行业标准。

长期保留现有 PRD 的验证目标：20 轮完整评审中至少 8 轮产生被保留并继续制作的作品。只统计明确完成评审的轮次，另列技术失败，不把未听任务算 Reject；少量试验不能证明稳定收敛。
