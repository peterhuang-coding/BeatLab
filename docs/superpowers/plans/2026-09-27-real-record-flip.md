# 尘里有金：真实老录音翻采草稿

2026-09-27 用户在合成人声闭环演示后提出：保留当前方向，但主要素材要由真实录音裁切，制作 Kanye 风格 beats，可委派 Coding Plan。

## 已定范围

交付一段约 54 秒、92 BPM、20 小节的可试听新草稿：高调女声采样、切片重排、明确主次、重鼓与留白，中段半拍律动转折后回归主题。参考制作语言，不采 Kanye 歌曲、不使用其人声。原作品保留。现有历史 blues/jazz 录音不是六十年代 soul，不把年代或纯人声分离伪造为事实。

主代理负责来源核验、原始窗口与变调选择、实际渲染、验收和交付。两路独立 cc-plan 负责可复用编排代码与采样工程/原句对照交付代码；同波最多 2 路，禁止按量兜底、未知重发。只交最小公开代码/合成测试，不传私人音频。

## 实施顺序

1. 校验现有 Citizen DJ 来源和本地 SHA；保存旧作品 SHA/mtime 基线。
2. 固定 prepared.json 契约：已处理切片、角色、真实源窗口、半音变化、拍长、低音参考音、来源；每条录音在本机裁切。区分不同窗口与已核实不同唱词，不凭窗口数冒充歌词多样性。
3. 并行委派编排与交付包：`beatlab-record-flip-compose-20260927-a1`、`beatlab-record-flip-delivery-20260927-a1`。固定暂存位置，结束后逐项核验原输入哈希、修改范围及测试，顺序采用。
4. 生成新版本 `gold-from-dust-20260927-v1`；不调用 TTS/振荡器生成主旋律或人声。鼓和 Bass 使用已有 Core Library one-shot 采样；完整来源记录留在本地。
5. 验证切片与来源一致、时长与MIDI、分轨还原、峰值/有限数、非目标旧作保持；实际原句→处理切片→混音对照。
6. 交付音频分轨 ALS、独立可触发 ChopRack 与映射 MIDI。Live 实际打开/重开/回渲染若未完成如实保留；不能把文件通过检查当作 Live 已验。
7. 代码、完整计划、来源说明与实际证据 commit/普通 push 执行分支；不提交媒体、不合 main。回写 Hub 和项目恢复点。试听判断和 Keep 由用户决定。

## 验收边界

真实录音裁切与技术验证不能证明好听。不同源区间不自动等于不同歌词；本轮不做唱词识别/纯净人声分离。最初合成演示的肯定不是对这首新草稿的 Keep。自动化闭环技术交付保留，当前先完成用户新授权的真实音乐草稿，不自动展开全量 PRD 或专辑九曲。
